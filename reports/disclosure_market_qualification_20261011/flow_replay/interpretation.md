# 订单流重放：结果解读（2026-10-12）

## 执行前审查与修订

接手的草稿 `cases=[]`、缺 `initial_manifest.json`。草稿原 hash 记录在 [initial_manifest.json](initial_manifest.json) 的 `draft_predecessors` 中。修订内容：

- `freeze.json`：按父档顺序补齐 60 个 case，写入原 JSON/NPZ 路径与 hash（与 `audit_validation.json` 的 `input_hashes` 逐个核对一致）、原状态、原机械状态和审计机械状态。其他字段未改。
- `run_frozen.py`：含股息矩的重算改为与原启动器完全一致（全有限才计算，`ValueError` 记为 NaN），避免出现假的逐字节不一致；每个世界开始前调用父启动器的 `verify_sources()`，确认 `abm` 从带 hash 绑定的隔离源码导入。
- 交接文档担心 EMA 的乘除次序不一致，这一点经核查不成立。归档 `market.py` 写的是 `(1 - rho) * flow_impact / depth_fraction`，从左到右求值即 `((1-rho)*u)/d`，与离线递推相同。重放中每日每家公司的源 EMA 和暂时冲击状态都逐字节一致，也证实了这一点。

## 执行结果

- `--check-only` PASS 后执行 `--run`：60/60 完成，0 中断，未新增种子，总耗时约 27 分钟（期间并行跑过全量测试，计时不能作为性能证据）。
- 每个世界的 23 个原 NPZ 数组均逐字节一致。59 个世界原结果指纹 PASS；`m30_710107` 原记录本来就没有指纹，因此标为 unavailable，没有补造。
- 新增内容只有逐日 u（目录共 310 MB，低于 900 MB 预算）。

## 离线预测比较（同一 u 单位，测量期 1201–3500 日，公司等权再世界等权）

| 臂 | current MSE / MAE / 误差 ACF1 | alternative MSE / MAE / 误差 ACF1 |
|---|---|---|
| m30 | 6.2868e-05 / 0.0053566 / −0.23340 | 6.3069e-05 / 0.0053631 / −0.23365 |
| m70 | 5.0515e-05 / 0.0047890 / +0.02049 | 5.0619e-05 / 0.0047920 / +0.02088 |

- 两臂全部 60 个世界里，alternative（对 u 本身做 EMA）的 MSE 和 MAE 都比 current（对 u/d 做 EMA 再乘回 d）略大：MSE 的相对差距在 0.13%–0.42% 之间。误差 ACF 的差异不到 0.001。
- 条件报价下的截断：原有 4 次截断全部保留，没有消失也没有新增；测量期两种写法都是 0 次。阈值附近（1e-12 以内）的值为 0 个。
- 4 次截断的分解：u 单位预测误差约 −0.14 到 −0.16，两种写法相差小于 1e-5；暂时冲击变化约 −0.24 到 −0.28，两种写法相差小于 2e-4。截断来自预热期很大的单日负向订单流本身，与预测写法无关。

## 能说什么、不能说什么

- 可以说：在固定的已实现输入下，换成另一种预测写法，既不能消除预热截断，也不能改变 m30 臂误差的强负自相关；按 MSE/MAE 衡量，它在每个世界都略差。所以"改预测公式"这条思路不应该作为修复市场反转或截断的手段。
- 不能说：这不是完整市场反事实（新写法会改变后续价格、订单和状态），不能证明 current 是最优预测，也不构成市场验收或参数选择。原 3 个机械 FAIL 和 4 次截断保持不变。
- m30 与 m70 两臂的已实现订单流不同，跨臂差异不只是预测记忆参数造成的。
